Developer handover

How to turn the working prototype into the production platform. All business rules already live in academy-core.js — port them to server functions; keep the pages as the UI reference.

2 · Tables (Supabase / Postgres)

Each prototype key maps to a table. Use uuid primary keys plus the human-readable references shown (unique). Every table: created_at, updated_at, created_by.

profilesauth.users 1:1 · name, phone, role[] · links to existing CRM client by phone (no duplicate people)
studentsprofile_id, student_ref (STU-…, unique), location, emergency, consent jsonb, alumni jsonb
instructorsprofile_id, title, bio, photo, verified_qualifications jsonb, active
courses · modules · lessons · quiz_questions · practical_itemscourse: code unique, product, level, modes[], requirements jsonb, requires_id, status · ordered children with position
cohorts · sessions · bookingsfees, deposit, instalments, capacity, access_from/to · session kind, private meeting_ref, recording jsonb · practical bookings
enquiries · applications · documentsapplication ref (APP-…), status, status_history, consent, account link · documents in private storage bucket with row per file
enrolments · lesson_progress · submissionsunique (student, cohort) · progress per lesson · quiz attempts, assignments, demo videos with grades
attendance · practical_evaluationsunique (session, student) with corrections[] · date, criteria, rating, outcome Pass/Resit/Pending, supervised, signed_off_by (append-only)
completions · certificatesrequirement snapshot · public cert ref unique, status Valid/Revoked, history[]
payments · refundsprovider_ref unique, kind, amount (GHS, numeric), status, webhook_payload, verified_at
events · event_registrations · articles · storiesCMS content; stories require consent = true to publish (check constraint)
messages · notifications · support · questions · audit_log · settingsqueued outbound messages with channel + status; audit is insert-only

3 · Row-level security

Studentselect own rows where student.profile_id = auth.uid(); insert own submissions, questions, support, bookings; never update grades, attendance or payments.
Instructorrows whose cohort.instructor_id = own instructor id; write attendance, grades, evaluations, lessons for those courses only.
Staff rolespermission table mirrors ROLES in academy-core.js (16 permissions). Check has_perm(auth.uid(), 'finance.verify') in policies and functions.
Publicpublished courses, cohorts (no private fields), events, articles, consented stories; certificate verification through a function returning only public fields.

4 · Server functions

submit_applicationvalidation + duplicate check + CRM link + notifications (from submitApplication)
payment_webhookverify provider signature → mark Verified → try_enrol. Never trust the browser’s success page.
try_enroloffer accepted + verified ≥ deposit → create/link student, enrolment, welcome message
eligibility · confirm_completion · issue_certificateport eligibility() exactly; issue only from a completion record; render PDF server-side with QR to the verify URL
send_messagescron: dispatch queued messages by consented channel; store provider id and delivery status
signed_media_urlshort-lived URLs for lesson video/PDF to enrolled students within access dates
