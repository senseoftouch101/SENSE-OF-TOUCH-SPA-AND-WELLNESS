Implementation plan

How the Institute plugs into the existing Sense of Touch platform — architecture, data, workflows, permissions, phases and acceptance tests. The working prototype lives in Institute (public), Institute Portal (students and instructors) and Institute Admin (staff), all sharing academy-core.js.

0 · Before launch: three decisions

1. Fees, durations and first intakesEvery course currently shows “To be confirmed”. Set tuition, registration fee, deposit, installment policy and dates per cohort.
2. Instructors and safety requirementsAppoint instructors beyond the founder, record their verified qualifications, and confirm the supervised-practice and hygiene rules per course.
3. Certificate wording and accreditationCertificates are internal certificates of completion. Only add an accreditation statement once documentary confirmation is on file.

1 · Audit of the existing platform

WebsiteDesign-component pages with a shared header and footer. Institute added as a nav item and its own sub-navigation.
Datasot-store.js keeps records in browser storage (prototype). Institute records use the same store under acad-* keys so the move to a real database is one migration.
Authenticationsot-auth.js: members, admin and staff accounts with one-time codes. Institute staff roles are assigned in Admin → Staff; the Institute Admin reads the same session.
CRMcrm-core.js merges clients by Ghana phone number. Institute enquiries and applications update an existing lead (matched by phone or email) instead of creating a duplicate.
PaymentsNo live provider yet. Shop and gift cards rely on staff verification — the Institute follows the same rule: access is granted only after verification.
CommunicationsWhatsApp links only. Institute messages are logged and queued with the channel chosen from each person’s consent, ready for a provider.

2 · Architecture

One platform, one database, one sign-in. The Institute is a module, not a separate app.

Public site
Catalogue, course pages, calendar, admissions, apply, track, verify, contact
Portal
Student LMS, schedule, results, payments, support · Instructor registers, grading, practicals
Admin Console
Institute Management module with role-scoped sections
Shared services
Supabase Postgres + Auth + Storage, row-level security, payment webhooks, message queue, PDF

Attendance, online completion, knowledge assessment, practical competency, overall completion and certificate issuance are separate tables by design.

4 · Key workflows

AdmissionsApply (validated, duplicate-checked) → reference issued, CRM lead updated, admissions notified → review → accept / waitlist / decline → applicant accepts offer on the Track page → payment instructions.
Payment → enrolmentPayer submits transaction ID → Pending verification → provider webhook (or finance, until connected) verifies → once the required deposit is verified, the student record is created or linked and the enrolment activates. A front-end success screen never grants access.
OnboardingEnrolment issues the student ID and links the shared Sense of Touch account → welcome message → first portal sign-in shows the handbook and policies to acknowledge (recorded) → timetable → lessons unlock within the cohort’s access dates.
Course productsEach course has a type: short introductory, professional certificate programme (subject to recognition), advanced specialist workshop, online self-paced, corporate training, train-the-trainer (subject to qualifications and approval). Revenue is reported per type.
Hybrid learningOnline theory lessons → knowledge checks (pass mark, limited attempts) → practical eligibility → supervised sessions with registers → practical competency recorded by an instructor → completion confirmed → certificate.
CertificatesEligibility is computed from the course’s configured requirements. Completion is confirmed by an authorised role; issuance creates a public ID, QR code and verification record. Revocations and corrections are logged and reflected on the verification page immediately.

5 · Integrations to evaluate

PaymentsPaystack (cards, MTN/Telecel/AirtelTigo MoMo) or Hubtel — choose on fees, settlement time and webhook reliability. Verify on the server only.
Live classroomGoogle Meet (if on Workspace) or Zoom. Links generated per session and shown only to enrolled students.
VideoAccess-controlled hosting with signed, expiring URLs and low-bitrate renditions for mobile data; audio + transcript fallback.
MessagingEmail provider; WhatsApp Business API with approved templates; SMS via Hubtel. Respect per-person consent.
Storage & PDFPrivate buckets for applicant documents (virus-scanned, type and size limited); server-rendered certificate PDFs.

6 · Phases

Phase 1Confirm the three decisions. Publish course pages, calendar and enquiry/interest capture into the CRM.
Phase 2Move data to Supabase with row-level security; applications, admissions, track-and-accept, staff roles, audit log.
Phase 3Payment provider + webhooks, automatic enrolment, receipts, balances, refunds, reconciliation.
Phase 4Student portal and LMS with video hosting, live classroom, instructor registers, grading and practical records.
Phase 5Certificates (PDF + QR + verification), messaging automations, reports; optional alumni module after the first cohort graduates.

7 · Acceptance tests

End to end: visitor → course → application → review → admission → payment → enrolment → student sign-in → learning → attendance → assessment → completion → certificate → verification. Load sample data in Institute Admin → Settings to walk it in the prototype.
