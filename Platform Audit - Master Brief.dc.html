1 · Fix first

These conflict with the brief’s security and identity rules.

Wrong main adminsot-auth.js and handoff/README.md make senseoftouch101@gmail.com the built-in administrator. The brief names admin@senseoftouch.co. Today that address only exists once the Gmail admin creates it under Admin → Official accounts.
Password in the codesot-auth.js contains a hash of the admin password. It is unsalted and short, so anyone who views the page source could recover it. Retire that password now. Never reuse it.
Two role systemssot-auth.js uses free-text staff roles. academy-core.js has its own list of 9 Institute roles. The brief asks for one system with 20 roles. The two need merging into one roles and permissions list.
Access is checked only in the browserEvery page hides admin screens on the visitor’s device, so anyone with technical skill can get past it. Fine for a prototype. Not acceptable once real data goes in.
Brand nameThe brief says “Aftercare”. The site, shop and 3D product viewer say “Aftercare”. Which is correct?
